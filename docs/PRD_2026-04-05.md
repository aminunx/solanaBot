# Solana Bot PRD — 2026-04-05

## Product
`solanaBot` is a Solana mainnet arbitrage and execution bot designed for strict capital protection first, then profit capture.

## Objective
Build a server-run Solana bot that:

1. scans real Solana markets continuously
2. rejects every candidate that fails a conservative no-loss law
3. prepares execution only when net profit remains positive after fees
4. sends privately through Jito only after the same law still holds at send time
5. measures treasury before and after every real execution

## Strategic Decision
The first Solana implementation is **scanner-first** and **no-loss first**.

Reason:
- modern Solana execution is sensitive to priority fees, landing probability, and bundle competition
- old sources describing legacy swap or flash-loan flows are not sufficient
- the correct starting point is current Solana RPC + current Jupiter routing + current Jito submission

## Market Logic
Initial strategy:
- round-trip opportunity scan across liquid Solana pairs
- first target markets:
  - `SOL/USDC/SOL`
  - `USDC/SOL/USDC`

The scanner uses live quote surfaces and current prioritization-fee samples.

## No-Loss Admission Law
Execution may proceed only if:

```text
conservative_final_out_usd
- principal_usd
- priority_fee_usd
- jito_tip_usd
- rpc_fee_usd
- safety_buffer_usd
> 0
```

This rule is the same project law used in the Base workstream, adapted to Solana fee mechanics.

## Execution Model
Phase 1:
- quote and scanner runtime
- priority fee discovery
- execution preflight artifact

Phase 2:
- sender path with signed versioned transaction
- Jito private send / bundle path
- on-chain treasury reconciliation

Phase 3:
- live loop with before/after treasury accounting
- only count success when full treasury delta is positive

## Infra
- network: Solana mainnet-beta
- routing: Jupiter
- private send: Jito Block Engine
- runtime host: Lightning server
- language: TypeScript

## Why Old Sources Are Rejected
This repo rejects:
- archived Solana Labs era execution assumptions
- deprecated Jupiter routing guidance when newer routing docs exist
- legacy public-mempool-first execution patterns that ignore Jito searcher reality
