# Solana Bot PRD - 2026-04-05

## Product
`solanaBot` is a Solana mainnet arbitrage bot built for strict capital protection first and profit capture second.

## Objective
Build a server-run Solana bot that:

1. scans real Solana markets continuously
2. rejects every candidate that fails a conservative no-loss law
3. prepares execution only when net profit remains positive after fees
4. submits privately through Jito only after the same law still holds at send time
5. measures treasury before and after every real execution

## Current Strategy Decision
The Solana workstream is now a direct-venue scanner, not an aggregator-vs-aggregator scanner.

Reason:
- Jupiter is an aggregator, not an independent venue
- comparing Jupiter against Raydium alone is structurally weak because Jupiter can already internalize Raydium routes
- the correct arbitrage surface is direct venue vs direct venue

## No-Loss Admission Law
Execution may proceed only if:

```text
conservative_final_out_usd
- principal_usd
- priority_fee_usd
- jito_tip_usd
- rpc_fee_usd
- safety_buffer_usd
> 0
```

Conservative output uses venue minimum-out values:
- Jupiter: `otherAmountThreshold`
- Raydium: `otherAmountThreshold`
- Orca: `tokenMinOut`

## Architecture

### Phase 1
- live quote scanner
- priority fee discovery
- execution preflight artifact

### Phase 2
- sender path with signed versioned transaction
- Jito private send path
- on-chain treasury reconciliation

### Phase 3
- continuous live watch
- real treasury accounting before and after every send
- only count success on positive full-treasury delta

## Infra
- network: Solana mainnet-beta
- direct venues: Raydium, Orca
- price reference: Jupiter
- private send: Jito Block Engine
- runtime host: Lightning server
- language: TypeScript

## Strategy Diagnosis
The first scanner used Jupiter on both legs and was not a true arbitrage engine.

The second scanner now uses direct Raydium and direct Orca quotes. This is the correct model, but current live scans still show negative raw round trips on the currently tested markets. That means the next engineering task is to expand direct venue coverage or market discovery, not to send faster.
